# Разработка «Севера»

Код и данные этой рабочей копии позволяют запустить диспетчерскую из чистого клона. Сохранённые смены создаёт тот, кто пользуется приложением. Для начала выполните команды запуска из [README](README.md).

## Где менять поведение

| Что меняется | Где внести изменение | Как проверить |
|---|---|---|
| Настраиваемое поле в смене или машине | Форма в `public/index.html`, чтение и восстановление в `public/app.js`, проверка и значения по умолчанию в `backend/service.mjs` | Введите значение, пересчитайте, обновите страницу. Откройте также смену без нового поля |
| Условие срочности или срок | `backend/policy.mjs` задаёт класс, срок и причину. Выбранные диспетчером направления проходят через `backend/service.mjs` | Проверьте прямое и обратное направления одной улицы, обычный проход и подтверждённый вызов |
| Учёт времени, стоимости или ограничений маршрута | `backend/planner.mjs` получает граф, проходы, парк и параметры смены | На малом примере сверьте расчёт вручную, на городской сети сравните бюджеты, возврат, назначенные проходы и своевременность по классам |
| Направление, доступ или состав перечня дорог | `tools/import_city.py` готовит снимок, `backend/policy.mjs` формирует задания. `data/CITY_SOURCES.md` описывает происхождение | При смене данных обновите версию и проверьте достижимость, перекрытия и возврат |
| Состояние участка на карте | `public/map.js`, `public/app.js` и стили в `public/` | Проверьте момент до, во время и после работы, участок с двумя направлениями, переезд и пропуск |

Перед началом изменения запишите, кто вводит параметр, в каких единицах, какое значение действует для старой смены и на какое решение диспетчера он влияет. Например, для новой характеристики техники определите, ограничивает ли она допуск на дорогу или меняет скорость выполнения работ. Сценарные значения подписывайте в интерфейсе и в источниках данных.

## Совместимость и версии

- Версия приложения находится в `package.json`. Для релизов используйте `vX.Y.Z` в Git. Исправление меняет Z, совместимая возможность — Y, несовместимый контракт — X. Коммит Git точно определяет проверенный код между релизами.
- Версия городской сети хранится в `data/city-network.json` в поле `version`. Импортёр использует префикс SHA-256 исходного PBF. Если изменились правила геометрии, доступности или формирования идентификаторов при том же PBF, задайте новой сети отличимую версию. Сервер восстанавливает последнюю смену для совпадающей версии сети.
- При изменении SQL добавляйте новую нумерованную миграцию в `drizzle/` и запись в `drizzle/meta/_journal.json`. Локальный сервер выполняет SQL-файлы при каждом старте, поэтому миграция должна быть безопасна при повторном исполнении. Проверьте пустую базу, существующую базу и повторный запуск.
- `GET /api/data` выдаёт каталог и последнюю смену, `POST /api/plans` возвращает `id`, `input`, `result`. Для ранее сохранённых входов сохраняйте значения по умолчанию. В результатах различайте запланированный рабочий проход и холостой переезд. Дедлайн относится к окончанию прохода, бюджет включает возвращение техники на базу.

## Что проверять перед слиянием

1. `npm test` проверяет маршруты, сохранение через API и расчёт на маленьких графах, где точный ответ можно перебрать.
2. `node tools/compare-plans.mjs` нужен для изменений расчёта. Сравнивайте одинаковую технику, бюджет, версию сети, число работ и версию Node. Различайте число назначенных заданий, объём сети в километрах и число своевременных проходов.
3. `npm run build` проверяет сборку облачной версии. `npm run demo` собирает автономную версию. При изменении формы или формата данных проверьте один сценарий в сервере и в автономном HTML.
4. В PR укажите, какую проблему решает изменение, как её повторить и какие результаты увидел второй участник. Сравнение по одной учебной смене характеризует выбранный сценарий.
