# Качество решений и проверка алгоритма

Не сравнивать планы только по «сумме километров». Нужен набор метрик при **одних и тех же данных**, версиях карт, доступных ресурсах и ограничениях.

| Метрика | Что считать | Ограничение интерпретации |
|---|---|---|
| Critical access | Время восстановления доступности больниц/пожарных/автобусных направлений | Список критичных объектов и критерии согласовать с заказчиком |
| On-time operations | Выполнено в применимый срок по виду операции | Срок и событие начала должны иметь проверенный источник |
| Coverage | Доля закрытых требуемых операций, а не просто длина всех дорог | Одна дорога может требовать разные действия/повторы |
| Makespan | Момент окончания последней машины | Только при сопоставимых объёмах выполненной работы |
| Deadhead | Км без работы | GPS не всегда определяет рабочий режим |
| Resource utilization | Время занятости vs доступность по смене | В простое бывают обязательные технологические операции |
| Cost | Расход по подтверждённой методике | Не приравнивать сметные цены к реальной себестоимости |
| Runtime | Время расчёта на фиксированном железе | Репрезентативная серия, не один запуск |

Метод: 1) synthetic test cases, 2) small exact solver/oracle for корректность, 3) реальные исторические смены в теневом режиме, 4) лишь потом контролируемая проверка в полях с разрешением. Отдельно фиксировать качество входных данных.
