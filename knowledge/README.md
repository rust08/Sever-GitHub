# Snow Control — база знаний (GitHub + Obsidian + Codex)

**Срез:** 20 ноября 2026. **Актуальная реализация:** `main` репозитория, а не этот документ. **Статус:** архитектура знаний и план задач, не юридическое заключение.

Откройте папку `knowledge/` как vault в Obsidian (`Open folder as vault`). Это обычные `.md`-файлы, доступные также через GitHub и Codex. GitHub — источник версий публичной базы, Obsidian — редактор. Облачная память диалога не заменяет репозиторий.

**Начало:** [Навигация](00_INDEX.md) → [Текущее состояние](01_PROJECT_STATE.md) → [Приоритеты](02_ROADMAP.md). Полная история реализованных работ остаётся в [research/BACKLOG.md](../research/BACKLOG.md) и [research/HANDOFF.md](../research/HANDOFF.md).

## Разделение доступа

- Эта папка находится в **публичном репозитории**. Здесь только несекретные технические сведения и публично опубликованные материалы.
- Не добавлять сюда контакты сотрудников, приватные интервью, внутренние поручения, телематику по водителям, неразрешённые PDF подрядчиков, реальные персональные данные или ключи.
- Отдельный **закрытый Obsidian Vault** из пользовательского архива храните вне этого репозитория. Перед передачей коллегам проверяйте допустимость доступа.
- Папка `knowledge/` **не** является хранилищем исходных PDF или подписанных контрактов. Ссылки на оригиналы — через реестр источников и разрешённое хранилище.

## Как работать

1. Новый участник читает `00_INDEX.md`, затем `01_PROJECT_STATE.md`.
2. Перед задачей смотрит **живой** `research/BACKLOG.md`, а не только дату заметок.
3. Изменил подход/границы задачи → новая запись в `decisions/`, с мотивами и проверками.
4. Нашёл факт → записал источник, период, охват, степень подтверждения в `research/EVIDENCE_RULES.md`.
5. Codex: читать корневой `AGENTS.md`, затем `knowledge/codex/WORKING_RULES.md` и лишь релевантную заметку. **Не читать все архивы целиком для каждой задачи.**
6. После изменений тесты `npm test`, `npm run build`, `npm run demo`; при изменении оптимизатора — `node tools/compare-plans.mjs`.

## Что НЕ является утверждением об актуальном состоянии города

Любые учебные приоритеты, скорости техники, тестовые договоры, модельные нормы, граф исходной сети и исторические упоминания подрядчиков — не подтверждение актуальной муниципальной действительности. Не заменять `unknown` цифрой по умолчанию без явной маркировки как `simulation`.
