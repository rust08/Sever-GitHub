|---|---|---|
| 1. Исследование | Полный ZIP, контрольные суммы | [Инструкция](README.md) |
| 2. Ответственность | Объект, владелец, балансодержатель, орган, исполнители и ответственный за поручение | В досье без документов перечисляются недостающие основания |
| 3. Допуск | 12 видов операций. Проверяются объект и вид работы в приложении, период и стороны договора, назначение техники и её допуск | Выберите участок вне учебного договора или замените патрульную расчистку на вывоз |
| 4. Срок | Учитываются версия и пункт правила, территория, документированная категория, период и вид начального события | В учебном договоре включите и выключите событие. Два часа в примере — сценарная величина |

| 6. Маршрут | Планировщик вызывается после проверки допуска. Берётся одна выбранная машина из сохранённой смены. Закрытия, направление, бюджет и возврат действуют | Закройте нужный участок, пересчитайте смену и снова проверьте допущенный наряд |
| 7. Прототип и регрессия | Карточка дороги, серверный API и автономный Worker используют одну модель. Существующие городские сценарии сохранены | `npm test`, `npm run build`, `npm run demo` |

## Четыре изменения для следующей смены команды

| В карточке учебного наряда | Что проверить вместе |
|---|---|
| Выбор машины из сохранённой смены | Сохраните смену с двумя машинами. По очереди выберите каждую для одной дороги. Сравните название, стоимость и длительность пробного маршрута. У каждой машины свой журнал. |
| Истёкший договор | Выберите досье «Договор истёк к началу смены». Виден конец действия договора по камчатскому времени, причина блокировки и отсутствие кнопки выдачи. |
| Момент окончания снегопада | Для действующего учебного договора включите событие и введите 45 минут. В смене с 08:00 событие наступает в 08:45, учебный срок — в 10:45. Два часа заданы для примера. |
| Скачивание карточки | Нажмите «Скачать карточку наряда (JSON)». Файл содержит режим симуляции, участок, смену, машину, досье, решение о допуске, расчёт срока и историю действий. Можно передать даже заблокированный пример. |

## Как продолжить вдвоём

Пока PR открыт, договоритесь, кто редактирует ветку `codex/governance-foundation`. Перед работой выполните `git fetch origin`, `git switch codex/governance-foundation` и `git pull --ff-only`. После проверки отправьте свой коммит командой `git push`. GitHub добавит его в тот же PR. Если PR уже слит, обновите локальный `main` и создайте от него ветку для следующей задачи.

Ближайшая задача — вместе с заказчиком разобрать одно обезличенное приложение к договору. Нужны границы участка, перечень работ, период действия и ответственный за выдачу поручения. Такой пример позволит проверить, какие поля из учебного наряда совпадают с рабочими документами.

## Как показать за две минуты

Запустите `npm start`, откройте городскую карту, нажмите доступную двустороннюю дорогу рядом с базой, затем «Проверить учебный наряд». Начните с отсутствующих документов. Сравните варианты «Участок вне учебного договора» и «Учебный договор на выбранный участок». Переключите событие о снегопаде, затем нажимайте кнопки действий и наблюдайте изменения журнала. Каждая комбинация участка, машины, направления, операции, досье и времени события в сохранённой смене имеет отдельный локальный журнал.

## Граница реализации

Вся работа с нарядом в этом выпуске — симуляция. Образец договора создаётся на один выбранный участок и один вид работ на дату учебной смены. Остальные операции представлены в классификаторе, для них можно проверить причину отказа. Полный городской план по-прежнему рассчитывает демонстрационные проходы. Пробный наряд использует бюджет отдельно, поэтому результаты двух расчётов нельзя суммировать как утверждённый план.

У проекта пока нет реестра реальных ответственных лиц, контрактов, действующих местных правил и погодных наблюдений. Появление P1 и плановое окончание прохода не порождают нормативную просрочку или приёмку. В учебном журнале роли и документы условные; данные сохраняются в браузере. Для реального исполнения нужны серверная авторизация, журнал с защитой от изменения, раздельные полномочия и хранилище доказательств.

## Откуда продолжить

Следующая самостоятельная ветка — импорт одного проверенного обезличенного договорного приложения. Попросите у заказчика паспорт участка, схему границ, стороны, полномочия, перечень операций, ресурсы и даты. Свяжите строки приложения с объектами сети вручную и сохраните происхождение. Покажите в том же интерфейсе неопознанную границу, истёкший договор и совпавший объект.

Дальше отдельными изменениями: версионный реестр норм с исключениями и реальными начальным и конечным событиями; серверные роли, акты, споры и устойчивый журнал; общий план по допущенным нарядам с резервированием машин и бюджета. Погрузка, вывоз, разрешённая площадка, совместная работа техники и повторный снегопад потребуют отдельных моделей. Основания для интервью — файл 06 архива. После появления этих данных сравните маршруты на одинаковом перечне разрешённых работ.

Проверка этой ветки: 20 исходных тестов и 11 тестов учебного наряда, обе сборки. Через Chrome проверены отсутствие документов, участок вне договора, появление учебного срока и повторное открытие смены в автономном HTML. Тесты в `backend/governance.test.mjs` адаптируют части сценариев T01–T09, T11, T18, T21, T24–T27 и T35; каждый тест называет конкретное проверяемое условие. Реестр оставшихся сценариев — файл 04 архива.
