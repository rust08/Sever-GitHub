## Этап 1 · серверный реестр ответственности

Запустите Node-сервер и откройте «Реестр ответственности · документы и редакции» под картой. Для первого показа выберите «Новая запись», подставьте учебный пример и сохраните. Повторно откройте редакцию после перезапуска сервера. Можно скачать строки JSON, изменить исполнителя, выбрать исходную редакцию и сохранить следующую. Старая редакция остаётся доступной. При одновременном редактировании сервер отклоняет запись с устаревшим базовым номером.

Для ввода одного участка без JSON откройте «Ввести одну адресную строку вручную», нажмите участок городской карты и «Взять выбранный на карте участок». Заполните стороны, период, операцию и основание. Режим «Документ на проверке» потребует сведения об объекте и PDF.

Для пакетного ввода документа на проверке укажите в JSON `mode: "document_review"`, номер договора, точный ID и версию сети, источник и пункт, дату начала и исключительную дату окончания, стороны, ответственного и проверяющего. Поля `objectType`, `jurisdiction`, `owner`, `balanceHolder` описывают тип объекта, юрисдикцию, владельца и балансодержателя по документу. Приложите PDF и HTTPS-ссылку на источник. Один импорт охватывает один договор, до 100 строк. При выпуске новой документальной редакции приложите соответствующий PDF снова. Реестр хранит оригинальные байты, SHA-256, снимок геометрии найденного участка, строки без геометрии и время записи. Юридическая проверка подписи и полномочий остаётся за заказчиком.

Данные хранятся в SQLite локального сервера в каталоге SNOW_DB_DIR (по умолчанию LocalAppData/SnowControlKamchatka на Windows). Автономный HTML и публичная сборка по-прежнему демонстрируют планирование. Учебная редакция открывается в карточке наряда. Документ на проверке сам по себе не разрешает выдачу. Следующий этап — исторические запросы и карта покрытия по операции и дате.

## Актуальная передача · адресное приложение

Рабочая ветка — `codex/territory-pilot`. Сводка по двум архивам и очередность работ — [незакрытые задачи](BACKLOG.md).

Выберите на карте дорогу, откройте учебный наряд, затем досье «Строки учебного приложения» и «Показать участок примера». В смене 2026 года для патрульной расчистки совпадёт одна строка; вторая попадёт в список строк без геометрии. Скачайте пример JSON. Чтобы проверить конфликт, продублируйте первую строку с другим номером договора и откройте изменённый файл. Выдача блокируется. При изменении даты пересчитайте смену: наряд использует дату сохранённого плана.

## Территориальная ответственность · второй архив

На городской карте выберите слой «Ответственность за расчистку · пилот». Он показывает геометрию 305 участков малого графа. В срезе на 20 ноября 2026 года для операции расчистки все 305 имеют статус «исполнитель не подтверждён». Нажмите на линию, чтобы увидеть название и исходные идентификаторы. Для возвращения к плану выберите «Приоритеты дорог».

[Территориальное исследование](Snow_Control_Territory_Responsibility_2026_11_20.zip) хранится целиком. Начните с файла `00_CODEX_START_HERE.md` внутри. Команда `python tools/import_territory_pilot.py` проверяет внутренний манифест, сверяет покрытие с геометрией и воспроизводит снимок для сайта. Статусы относятся только к участкам пилота, операции и дате среза. Исторические сообщения и закупки сами по себе не подтверждают назначение.

Для рабочего режима остаётся импорт документированной строки приложения к договору с периодом, операцией, точной ссылкой на основание и проверяющим. Понадобится сверить границы пилотного и городского участков, а пересекающиеся назначения вывести на ручную проверку. Учебный наряд и расчёт смены продолжают работать отдельно.

| В карточке учебного наряда | Что проверить вместе |

| Выбор машины из сохранённой смены | Сохраните смену с двумя машинами. По очереди выберите каждую для одной дороги. Сравните название, стоимость и длительность пробного маршрута. У каждой машины свой журнал. |
| Истёкший договор | Выберите досье «Договор истёк к началу смены». Виден конец действия договора по камчатскому времени, причина блокировки и отсутствие кнопки выдачи. |
| Момент окончания снегопада | Для действующего учебного договора включите событие и введите 45 минут. В смене с 08:00 событие наступает в 08:45, учебный срок — в 10:45. Два часа заданы для примера. |

## Как продолжить вдвоём

Пока PR открыт, договоритесь, кто редактирует ветку `codex/territory-pilot`. Перед работой выполните `git fetch origin`, `git switch codex/territory-pilot` и `git pull --ff-only`. После проверки отправьте свой коммит командой `git push`. GitHub добавит его в тот же PR. Если PR уже слит, обновите локальный `main` и создайте от него ветку для следующей задачи.

Ближайшая задача — вместе с заказчиком разобрать одно обезличенное приложение к договору. Нужны границы участка, перечень работ, период действия и ответственный за выдачу поручения. Такой пример позволит проверить, какие поля из учебного наряда совпадают с рабочими документами.

## Как показать за две минуты

Запустите `npm start`, откройте городскую карту, нажмите доступную двустороннюю дорогу рядом с базой, затем «Проверить учебный наряд». Начните с отсутствующих документов. Сравните варианты «Участок вне учебного договора» и «Учебный договор на выбранный участок». Переключите событие о снегопаде, затем нажимайте кнопки действий и наблюдайте изменения журнала. Каждая комбинация участка, машины, направления, операции, досье и времени события в сохранённой смене имеет отдельный локальный журнал.

## Граница реализации

Вся работа с нарядом в этом выпуске — симуляция. Образец договора создаётся на один выбранный участок и один вид работ на дату учебной смены. Остальные операции представлены в классификаторе, для них можно проверить причину отказа. Полный городской план по-прежнему рассчитывает демонстрационные проходы. Пробный наряд использует бюджет отдельно, поэтому результаты двух расчётов нельзя суммировать как утверждённый план.

У проекта пока нет реестра реальных ответственных лиц, контрактов, действующих местных правил и погодных наблюдений. Появление P1 и плановое окончание прохода не порождают нормативную просрочку или приёмку. В учебном журнале роли и документы условные; данные сохраняются в браузере. Для реального исполнения нужны серверная авторизация, журнал с защитой от изменения, раздельные полномочия и хранилище доказательств.

## Откуда продолжить

Следующая самостоятельная ветка — импорт одного проверенного обезличенного договорного приложения. Попросите у заказчика паспорт участка, схему границ, стороны, полномочия, перечень операций, ресурсы и даты. Свяжите строки приложения с объектами сети вручную и сохраните происхождение. Покажите в том же интерфейсе неопознанную границу, истёкший договор и совпавший объект.

Дальше отдельными изменениями: версионный реестр норм с исключениями и реальными начальным и конечным событиями; серверные роли, акты, споры и устойчивый журнал; общий план по допущенным нарядам с резервированием машин и бюджета. Погрузка, вывоз, разрешённая площадка, совместная работа техники и повторный снегопад потребуют отдельных моделей. Основания для интервью — файл 06 архива. После появления этих данных сравните маршруты на одинаковом перечне разрешённых работ.

Проверка этой ветки: 20 исходных тестов и 11 тестов учебного наряда, обе сборки. Через Chrome проверены отсутствие документов, участок вне договора, появление учебного срока и повторное открытие смены в автономном HTML. Тесты в `backend/governance.test.mjs` адаптируют части сценариев T01–T09, T11, T18, T21, T24–T27 и T35; каждый тест называет конкретное проверяемое условие. Реестр оставшихся сценариев — файл 04 архива.
